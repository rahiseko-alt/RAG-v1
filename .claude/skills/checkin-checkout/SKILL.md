# チェックイン / チェックアウト（簡易引継ぎ）

セッションをまたぐ**揮発的な文脈**を、軽量な `docs/handoff.md` 1ファイルで持ち回る仕組み
（詳細は `AGENTS.md`「セッション開始/終了の儀式」）。

## 大原則

- **handoff は `docs/handoff.md` に置く**：①今回実施 ②今回トラブル ③次回やる事の3項目。
- **handoff は上書き（最新1件）／失敗は蓄積**：ミス・失敗の記録は上書きだと消えて意味がないので、
  `docs/failures.md` に **append（消さない）** で積む。handoff の②はあくまで「今回セッションの揮発メモ」。
- **「軽量」の範囲は handoff の書式・更新義務だけ**：`docs/handoff.md` を書くかどうか・どこまで
  詳しく書くかはセッションの作業量に応じて判断してよく、CIによる更新強制も無い。一方、PRをCIが
  緑になるまで確認してマージする、という通常のPR運用（下記②手順4-5）は軽量化の対象外。

## handoff の構造（固定3項目）

- **①今回実施**：このセッションで何をやったか。
- **②今回トラブル**：ハマり所・環境の癖・暫定判断。特筆無しなら「無し」。
- **③次回やる事**：次の一手。特筆無しなら「特になし」。

## ① チェックイン（セッション開始時 = 読む）

1. `docs/handoff.md` を読む。
2. ①今回実施・②今回トラブルを1〜2行で要約してユーザーに提示する。
3. その内容と③次回やる事を踏まえ、「今回のセッションで何をやるか」を提示する
   （③を第一候補に、handoff が示す残課題があれば並べる）。

## ② チェックアウト（作業に区切りをつける = 書く）

意味のある作業を終えた、または区切りをつけるタイミングで実行する。

1. **前回の値を消してから**、今回の値で `docs/handoff.md` を上書きする：
   - ①今回実施
   - ②今回トラブル（無ければ「無し」）
   - ③次回やる事（無ければ「特になし」）
2. **失敗があれば `docs/failures.md` に1件 append**（日付＋事象＋根因＋教訓）。ここは消さない。
3. `docs/handoff.md`（＋あれば `docs/failures.md`）を保存し、**commit & push** する。
4. **PRを出す／既存PRへの反映を確認する**。このブランチに対応するPRが無ければ新規作成する（テンプレがあれば従う）。
   既にPRがある場合は、今回のpushがそのPRに乗ったことを確認する。
5. **CIの完走を確認し、緑ならマージまで実行する**（AGENTS.md「検証の規律」の運用に従う）。
   チェックアウトは**マージ完了まで**を完了条件とする。
   - 必須チェック（`ci-green`）が緑になるまで確認する。CIが赤・実行中のままではマージしない。
     マージ操作は GitHub のマージ機能（native auto-merge の有効化、または直接マージ）で行う。
   - **例外＝マージしない／保留する場合**は、その理由をチェックアウト報告に明記する（例：CIが赤、
     レビュー対応が積み残っている等）。理由なく「未マージのまま」でチェックアウトを終えない。
6. マージ後、次回チェックインが最新 `main` から始まるよう、後続作業が必要な場合は改めて `main` から
   ブランチを作り直す（マージ済みブランチへの追いpushはしない）。
