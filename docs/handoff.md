## ②今回トラブル

**2件とも自分の手順の問題で、片方は他者の成果を消した。**

1. **他セッションの作業を force-push で消した。** 同じブランチ名を別セッションが使っており、
   そちらの実装と PR があった。`git checkout -B <branch> origin/main` でローカル参照を作り直した
   直後に `--force-with-lease` で push したため、**リースの基準が古くなり安全装置が素通りした**。
   reflog から復旧し、内容を比較したうえで**別セッションの実装（品質が上）を採用**、自分の実装は
   破棄した。**ブランチを作り直す前に `git log origin/main..origin/<branch>` で他者の未マージ
   作業を確認すること。**
2. **「主張どおりの経路を通っていないテスト」を同じ日に3回書いた。** 前日に同種の失敗を記録した
   直後にもかかわらず繰り返した。特に 2 例は**テスト側で前処理をしてから比較**しており、
   その前処理を担うはずの本体コードが検証対象から外れていた。3例目は CodeRabbit の指摘で発覚。
   **新しいテストは、検証したい経路を壊して落ちることを確認してから通す。**

いずれも `docs/failures.md` に事象・根因・教訓を追記済み。

### 作業開始時の必須確認（今回の事故を踏まえて）

```bash
git fetch origin
git log --oneline origin/main..origin/claude/checkin-8obqof   # 出力があれば他セッションの未マージ作業
```

**出力があればブランチを作り直してはならない。** `--force-with-lease` は参照を作り直すと効かない。
