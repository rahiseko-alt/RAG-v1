# medguide-rag 運用ワークベンチ取扱説明書

## 1. この画面でできること

非エンジニアが、質問、回答検品、ナレッジ修正、変更前後の比較、全件回帰検査、承認・却下、監査確認をブラウザだけで行う。

通常運用にGitHub、CLI、SQLiteの直接操作は使わない。

## 2. 回答が表示される条件

処理順は次のとおり。

`質問 → 意味検索 → 根拠候補確認 → 回答候補生成 → 機械検査 → 別LLM照合 → 出荷判定 → 監査記録`

回答は次をすべて満たす場合だけ表示される。

- 引用番号が取得チャンクに実在する
- 事実を述べる文に引用がある
- 回答中の全主張が検証対象になっている
- 全主張が根拠に支持されている
- 根拠忠実性、質問直接性、誤情報なしがすべて2点
- 検証LLMが正常終了し、判定JSONが有効

「これは学習用デモです」という注意書きは回答本文へ生成せず、UIの固定表示として管理する。注意書きは回答検品の対象データに混ぜない。

矛盾、判断不能、引用破損、検証エラー、timeoutはすべて出荷停止になる。停止候補の本文は回答欄、`POST /ask`の`answer`、CLI標準出力へ出さない。

## 3. 4つのタブ

| タブ | 用途 |
|---|---|
| 質問・検品 | 質問し、回答、検品点数、主張と根拠、処理工程を確認する |
| ナレッジ調整 | Markdown/Textを編集、またはPDFを差し替えて下書きrevisionを作る |
| 比較・承認 | 1問比較または評価セット全件検査を実行し、合格版だけ承認する |
| 台帳・監査 | 変更内容、SHA、採否理由、副作用、run ID、Langfuse traceを確認する |

## 4. 良いか悪いかの判断

類似度は検索候補の近さであり、回答の正確性ではない。値だけで合否を決めない。

| 表示 | 判断 |
|---|---|
| 回答可能 | 全検査を通過し、回答を表示してよい |
| 出荷停止 | 根拠不足、矛盾、判断不能、形式不良、検証障害のいずれか |
| 処理失敗 | RAG、DB、LLM、監査処理などが完了していない |

主張ごとの根拠欄で、回答中の文とチャンク原文が実際に対応しているかを確認する。「検索詳細」を開くと全取得候補、順位、チャンクID、原文抜粋、類似度を確認できる。

## 5. どこを調整するか

| NG工程 | 主な原因 | 調整対象 |
|---|---|---|
| ナレッジ選択 | 対象文書が違う | 有効revision、出典、文書構成 |
| 意味検索 | 必要箇所を取得できない | 見出し・表現、チャンク分割、top-k、評価質問 |
| 根拠候補確認 | 原文が不足・矛盾 | ナレッジ本文、出典の追加・整理 |
| 回答生成 | 根拠はあるが回答形式が悪い | 生成プロンプト、生成モデル |
| 回答照合 | 主張が未支持・判断不能 | ナレッジ不足、回答の断定、検証条件 |
| 出荷判定 | 検証エラー・timeout | API設定、モデル設定、接続状態 |
| 監査記録 | Langfuse未着弾 | Langfuse URL・キー・ネットワーク |

## 6. 調整手順

1. `質問・検品`で問題を再現し、NG工程と根拠を確認する。
2. `ナレッジ調整`で変更概要、操作者、出典URL、本文またはPDFを登録する。
3. `比較・承認`で対象質問のbefore/afterを比較する。
4. 評価セット全件検査を実行する。
5. 対象質問が改善し、既存PASSが1件もNG化していない場合だけ承認する。
6. `台帳・監査`で変更前後SHA、回答差分、副作用、採否理由、traceを確認する。

全件検査に失敗したrevision、検査後にファイル・評価セット・エンジン設定が変わったrevision、却下済みrevisionは承認できない。承認APIはHTTP 409を返す。

## 7. 処理工程の読み方

通常は工程名と状態だけが見える。工程を開くと次を確認できる。

- 目的
- 入力
- 実行した処理
- 処理後の出力
- 判断基準

実行中の工程は自動展開し、完了後は閉じる。NG工程と出荷停止工程は開いたまま残る。

## 8. 監査確認

各質問にはローカルrun IDとLangfuse trace IDが付く。`台帳・監査`の「着弾を確認」は最大60秒pollし、次を表示する。

- ローカル保存状態
- Langfuse着弾状態
- trace ID
- run ID
- observation名
- SDKが生成したtrace URL

期待するobservationは`retrieve`、`generate`、`verify`、`gate`。監査ログは書き換えず、問題がある場合はナレッジまたは設定を新しいrevisionとして調整する。

## 9. 運用上の前提

初期納品は単一Windows PC、非エンジニア1名、localhost運用。認証、複数ユーザー権限、個人情報マスキング、クラウド公開、バックアップ運用は次段階。

Langfuseを有効にすると質問、検索・生成処理、品質判定の監査情報がLangfuse Cloudへ送信される。機密文書を扱う場合は、保存地域、保存期間、アクセス権限、送信可否を導入前に決める。
