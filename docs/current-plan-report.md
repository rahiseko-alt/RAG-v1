# medguide-rag 現在地と全体計画

## 現在地の補正

このプロジェクトは、現時点では「RAG品質改善ワークベンチ」ではなく、**OpenAI対応RAG・FastAPI最小API・Langfuse連携経路を備えた実証プロトタイプ**である。

CLIでのOpenAI回答生成、Langfuse SDK認証、RAG検索、出典付き回答は確認済み。ただし、Langfuse画面でのtrace着弾確認、実uvicorn経由の `/ask` E2E、非エンジニア向けUI、工程診断、調整台帳、before/after改善管理は未実装。

## UI/取説で必ず明示すること

- 類似度は「文書候補の近さ」であり、回答の正しさではない。
- 回答の信頼性は、根拠カバレッジと回答照合で判断する。
- このデモは医療助言ではない。診断、治療、投薬、緊急時対応には使わない。
- 監査ログは証跡であり、問題があればログを書き換えず、システム側を調整して再評価する。

## 調整管理に必要な最小項目

| 項目 | 内容 |
|---|---|
| adjustment_id | 調整を一意に追えるID |
| question_id | どの質問で問題が出たか |
| before | 調整前の回答、根拠、評価スコア |
| diagnosis | 失敗工程と原因分類 |
| adjustment | 何をどう変えたか |
| after | 調整後の回答、評価スコア |
| side_effect_check | 他の質問に悪影響が出ていないか |
| decision | 採用/却下/保留 |

## 次の実装順

1. Web UIを作る。
2. 回答、根拠パネル、処理タイムライン、監査状態を表示する。
3. 類似度の注意書きをUIに固定する。
4. `/ask` の実uvicorn E2Eを記録する。
5. Langfuse画面でtrace着弾をスクショ/記録する。
6. 診断スコアカードと調整台帳を追加する。
