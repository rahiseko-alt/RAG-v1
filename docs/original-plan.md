弱点克服のための開発練習シナリオ
Python ML/DL経験の不足を、既存の強み（プロンプトエンジニアリング・検証ループ設計）に接続しながら埋める、4段階・約6週間の計画です。

**01 / 1週間 / Python基礎の再固め**
STAGE 1 — FOUNDATIONS
公開医療系データセット（例: UCI Heart Disease、MIMIC-III デモ版等）を使い、pandas / numpy で前処理・簡易統計・可視化まで一通り手を動かす。目的は精度ではなく「Pythonでのデータ操作に迷いがない」状態を作ること。

技術: pandas / numpy / matplotlib

**02 / 2週間 / 軽量モデルを1本、完走させる**
STAGE 2 — ONE COMPLETE MODEL
scikit-learn または PyTorch で、分類か時系列予測のどちらかシンプルなタスクを最後まで通す（学習→評価→簡易チューニング）。SOTA精度は狙わず、「モデル開発を自分の言葉で語れる実体験」を1件作ることが目的。

技術: scikit-learn / PyTorch / 評価指標設計

**03 / 2週間 / 医療文書RAGを構築する**
STAGE 3 — RAG PROTOTYPE
公開されている医療ガイドライン文書を対象に、LangChain / LangGraph + ベクトルDB（Chroma等）で質問応答システムを構築する。ここは既存の強み（プロンプトエンジニアリング）と直結する領域であり、学習効率が最も高いステージ。歓迎スキルのRAG・LangChain経験をここで実体験として獲得する。

技術: LangChain / LangGraph / Chroma / Python API

**04 / 1週間 / 評価ループを移植する**
STAGE 4 — EVALUATION LOOP
02章で運用してきた「検証パネル」（複数視点でのLLM反証レビュー）の考え方を、Stage 3のRAGシステムの回答品質評価に転用する。LLM-as-judgeによる自動評価＋人手サンプリングの二段構えを組み、既存の運用ノウハウが新規ドメインでも通用することを自分自身で確認する。
